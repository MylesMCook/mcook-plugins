# Deploy To Cloudflare Workers

Cloudflare Workers is the main exception to the Go-first server default. Use TypeScript here because Workers is a JavaScript-native edge runtime and Cloudflare maintains a current MCP starter and transport wrapper for it.

Do not move a normal Go service to Workers merely to follow an example. Choose this path when Workers is the actual hosting target.

## Start From The Current Official Template

```bash
npm create cloudflare@latest -- my-mcp-server \
  --template=cloudflare/ai/demos/remote-mcp-authless
cd my-mcp-server
npm install
```

Inspect the generated dependency versions and commit the lockfile. Do not copy an older `McpAgent` tutorial into a new project.

## Current Server Shape

For a new stateless server, use an MCP SDK v2 server factory with Cloudflare's `createMcpHandler`:

```typescript
import { McpServer } from "@modelcontextprotocol/server";
import { createMcpHandler } from "agents/mcp/server";
import { z } from "zod";

function createServer() {
  const server = new McpServer({
    name: "acme",
    version: "0.1.0",
  });

  server.registerTool(
    "search_items",
    {
      title: "Search items",
      description: "Use this when the user needs to find items by keyword.",
      inputSchema: z.object({
        query: z.string().min(1).describe("Keywords to search for."),
      }),
      annotations: {
        readOnlyHint: true,
        idempotentHint: true,
        destructiveHint: false,
        openWorldHint: false,
      },
    },
    async ({ query }) => {
      const items = await searchItems(query);
      return {
        content: [
          {
            type: "text",
            text: `Found ${items.length} matching items.`,
          },
        ],
        structuredContent: { items },
      };
    },
  );

  return server;
}

const handleMCP = createMcpHandler(createServer, {
  route: "/mcp",
});

export default {
  fetch(request, env, ctx) {
    return handleMCP(request, env, ctx);
  },
} satisfies ExportedHandler<Env>;
```

Reconcile the exact imports and registration API with the generated template and pinned package versions. The template is the executable source of truth when it differs from this compact shape.

## Protocol Policy

- Use `/mcp` for new connections.
- Keep ordinary server creation stateless and request-scoped.
- The current Cloudflare handler serves MCP `2026-07-28` and compatible legacy stateless clients on the same route.
- Do not add Durable Objects for protocol sessions to a new ordinary integration server.
- Use a separate state store only for real application state keyed by authenticated principal or domain identity.

`McpAgent` is deprecated and feature-frozen. Preserve it only while migrating an existing server that still relies on sessionful behavior. Do not choose it for greenfield work.

## Authentication And Secrets

- use `wrangler secret put` or Cloudflare's supported secret storage
- authenticate before dispatching tool logic
- validate issuer, audience, expiry, and scopes
- do not pass the incoming MCP bearer token through to another service
- keep CORS and browser Origin handling explicit

## Run And Deploy

Use the scripts generated by the template. The usual loop is:

```bash
npm run dev
npm test
npm run deploy
```

Confirm the deployed endpoint ends in `/mcp`. Then validate it with MCP Inspector, ChatGPT, and another real client before advertising broad compatibility.

## Migration Check

For an existing `McpAgent` project:

1. inventory sessionful features such as protocol sessions, pushed requests, replay, or standalone streams
2. move ordinary tools, prompts, and resources into an SDK v2 server factory
3. add the stateless `createMcpHandler` route
4. run legacy and modern paths side by side only while required
5. remove the legacy route after supported clients and features have migrated

Do not call a transport rewrite complete until the deployed route passes the compatibility matrix you publish.
