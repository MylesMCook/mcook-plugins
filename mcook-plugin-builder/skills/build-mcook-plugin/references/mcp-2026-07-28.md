# MCP 2026-07-28 target

Use this reference only when implementing, reviewing, or packaging an MCP server that explicitly targets MCP `2026-07-28`.

## Keep the contracts separate

Agent Plugins `mcp.json` is launch and connection configuration. It does not declare the MCP wire-protocol version. MCP protocol selection and negotiation happen when the client connects to the server.

Codex 0.147.0 supports MCP `2026-07-28` behind the disabled-by-default `mcp_2026_07_28` feature. Preserve legacy behavior unless the server actually passes the modern protocol checks.

For Codex stdio testing, both sides of the opt-in are required:

1. Start Codex with `codex --enable mcp_2026_07_28`.
2. Put `CODEX_MCP_PROTOCOL_VERSION=2026-07-28` in that stdio server's configured environment.

The environment marker is Codex-specific. It is not an Agent Plugins schema field and does not prove that the server implements the protocol.

## Modern server contract

A server claiming MCP `2026-07-28` must account for the complete revision, including:

- implement `server/discover` and advertise versions, identity, and capabilities;
- remove the `initialize` and `notifications/initialized` handshake;
- process protocol version and client capabilities from each request's `_meta`, and return server identity in result `_meta`;
- return a required `resultType`, using `complete` or `input_required`;
- implement multi-round input through `InputRequiredResult` and retried original requests instead of server-initiated requests;
- paginate discovery and return deterministic tool ordering;
- include `ttlMs` and `cacheScope` on cacheable list/read results;
- remove protocol-level sessions and `Mcp-Session-Id` from Streamable HTTP;
- replace the old GET notification stream and resource subscription methods with `subscriptions/listen`;
- treat broken response streams as lost requests rather than resuming with SSE event IDs;
- move tasks to the `io.modelcontextprotocol/tasks` extension;
- avoid new dependencies on deprecated Roots, Sampling, Logging, Dynamic Client Registration, or HTTP+SSE behavior.

Also cover the new error codes, JSON Schema 2020-12 behavior for tool schemas, structured content accepting any JSON value, trace-context metadata, and authorization issuer/client-registration requirements when those surfaces apply.

## Verification gate

Do not claim MCP `2026-07-28` compatibility from a successful process launch or `tools/list` alone.

1. Run the server SDK's protocol and schema tests.
2. Exercise `server/discover`, paginated discovery, ordinary `complete` results, and at least one `input_required` retry.
3. Verify cache metadata on every affected result type.
4. Test the actual declared transport. For Streamable HTTP, include headers, redirect handling, request loss, and the subscription stream where supported.
5. Run a Codex session with `mcp_2026_07_28` enabled. For stdio, include the environment marker above.
6. If dual-protocol support is claimed, run a separate default-mode Codex session and verify the legacy lifecycle. Do not infer backward compatibility from modern-mode success.

Non-blocking MCP startup in Codex 0.147.0 is client behavior, not a server conformance claim.
